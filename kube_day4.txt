
## diffn betn microservices and monolithic architecture...

## microservices
1. every unit of the entire application should be the smallest, 
and it should be able to deliver one specific business gaol.
2. servic startup is relatively quick
3.fault isolation is easy. even if one service goes down
other can continue to function. 
4. all microservices are loosly coupled so that changes 
made in one does not affect the other.
5. bussiness can deploy more resources to servic that are 
generating more ROI.
6.more hardware resources could be allocated to the servic that is 
frequently used.so, more resources could be allocated to 
the search and product listning microservices.
7. Microservices always remains consistent and continously 
availabel.

## Monolithic architecture
1.a single code base for all business gaol
2. service - startup take more time. 
3. fault isolation is difficult. if any specific feature is not working,
the complete system goes down. in order to handle this issue, application 
need to rebuit retested and also redeployed.
4. Monolithic architecture is tightly coupled. changes in one module of code 
affect the other.
5.Since services are not isolated, individual resource allocation not possible.
6. application scalling is challenging as well as wastfull.
7. Development tools get overburdened as the process needs to start from the scratch.

## Q: What is the difference between kubectl create and kubectl apply?

kubectl create is an imperative command used to create Kubernetes resources. If the resource already exists, it throws an error.

kubectl apply is a declarative command used to create or update Kubernetes resources based on configuration files. 
It compares the desired configuration with the existing resource and applies the necessary changes.

## how to deploy a project on kubernets

steps 
1. creat a cluster
2. create a folder using mkdir foldername
3. verify folder created - ls
4. go inside the folder - cd folder name 
5. clone git repo of googlecloude demo micro service - git clone https://github.com/GoogleCloudPlatform/microservices-demo/tree/main
6. go to the relese folder because thats where thekubernetes-manifests.yaml file is placed. using cd 
7. create deployment - kubectl apply -f kubernetes-manifests.yaml
8. containers will be created, services will be created and your all service applications will be deployed.
9. verify by commands - kubectl get po %% kubectl get deploy && kubectl get svc
10. copy the external ip of frontend and run it in your browser
