
## what are logs and metrics
1. What are Logs?
Logs are records of events that happen inside an application or system.
They tell us what happened, when it happened, and sometimes why it happened.
For example, imagine you deployed a microservice application on Kubernetes.

Your application might generate logs like:

10:00:01 INFO  Application started successfully
10:00:05 INFO  Database connection established
10:00:10 ERROR Failed to connect to database
10:00:15 WARN  Retrying database connection
10:00:20 INFO  Database connection restored

Why do we need logs?
- To troubleshoot application errors.
- To understand why an application crashed.
- To identify failed database connections.
- To investigate security issues.
- To understand the sequence of events.
Think of logs as the diary of your application.

2. ## What are Metrics?
Metrics are numerical measurements collected over time to understand the performance and health of a system.
Unlike logs, metrics generally focus on numbers rather than individual events.

Metric	Value
CPU utilization	            75%
Memory utilization	        80%
HTTP requests per second	500
Application response time	200 ms
Failed requests	            25
Running pods	            5

Why do we need metrics?
- Monitor CPU and memory utilization.
- Monitor application performance.
- Track incoming requests.
- Identify performance bottlenecks.
- Set alerts when resource usage becomes too high.
- Understand application traffic trends.
Think of metrics as the health report of your application.

## HPA - horizantal pod autoscalling practical.....
create a cluster
Steps

3. Create an Nginx Deployment with Resource Limits ,create a .yamal file - vi nginx-deployment.yaml 
   paste 
   ---
   apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 2  # Initial number of replicas
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx
        resources:
          requests:
            cpu: "250m"
          limits:
            cpu: "500m"
        ports:
        - containerPort: 80
		
		
		
4. apply deployment manifest
kubectl apply -f nginx-deployment.yaml		
5. Verify the deployment 
kubectl get pod
kubectl get deploy 
kubectl describe deployment nginx-deployment

6. Expose Nginx Service 
 kubectl expose deployment nginx-deployment --type=LoadBalancer --port=80 --name=nginx-service
 
7. Verify the service:
 kubectl get svc 
 
8.Enable Metrics Server (If Not Already Installed - GKE usually 
comes with the Metrics Server pre-installed, but you can install it manually if needed:)

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

9. Verify the metrics server:
kubectl get apiservices | grep metrics

10. Create HPA for Nginx Deployment
 Run the following command to create an HPA that scales pods between 2 and 5 replicas based on CPU usage:
 kubectl autoscale deployment nginx-deployment --cpu-percent=2 --min=2 --max=5
 Verify the HPA configuration:
kubectl get hpa
expected outcome 
 NAME                REFERENCE                   TARGETS    MINPODS   MAXPODS   REPLICAS   AGE
nginx-deployment   Deployment/nginx-deployment  0%/50%     2         5         2          1m


11. Simulate High CPU Load to Test Scaling 
Deploy a Load Generator Pod (to stress the CPU and trigger HPA)
kubectl run -it --rm --image=busybox load-generator -- /bin/sh

12. Inside the container, run a loop to generate CPU load.
while true; do wget -q -O- http://nginx-service; done

13. Observe HPA scaling the pods: 
kubectl get hpa
kubectl get pods -w

14. Cleanup (Optional)
After testing, clean up your resources:

kubectl delete hpa nginx-deployment
kubectl delete deployment nginx-deployment
kubectl delete svc nginx-service

Final Output & Result
Initially, there are 2 Nginx pods.
When CPU usage exceeds 50%, HPA scales up the pods dynamically (up to 5).
If CPU load reduces, HPA scales down the pods.
This ensures efficient resource utilization and cost management.

## kubernetes comman erros and solutions

1. pods not starting 
pc - insufficient resource, image errors
solutions - check resource limit, ensure correct image name, tag.

2. service not accessible 
pc - Misconfigured service, Network policies 
solutions - verify service configuration, check network policies.

3. persistent volume claim issues
pc - inssufficient storage, access mode mismatch issues
solutions - ensure adequate storage, match pvc and pv access mode.

4. configmap key not found
pc - missing key in config map 
solutions - add the missing key to the config map

5. crashloopbackoffstatus
pc - private image withouth creadentials , wrong image name
solutions - provide image pull secrete, verify image name and tag.

6. Node not ready 
pc - Network issue, Disk pressure, invalid token/certificate, access.
solutions - check node , network connectivity, token/certificate , free up disk space.

7. failed scheduling 
pc - taints and tolerations mismatch, insufficient storage.
solutions - adjust taint and tolerations, ensure resource availability.

8. RBAC authorization error 
pc - incorrect role binding, missing permissions
solutions - review and correct role bindings, 
add neccesary permissions.

9. ingress controller
pc - misconfigured ingress, SSL/TLS problems.
solutions - verify ingress configuration, check SSL/TLS Certificates.
